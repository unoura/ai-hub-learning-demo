# 設計: 手順2 IRISSECURITY 暗号化

## ねらい

`IRISSECURITY.DAT` を暗号化し、格納される認証情報・Wallet のシークレットを**保存時(at-rest)で保護**する。
手順3で Wallet に入れる API キーが暗号化される前提を作る。

> **注意**: 参照元(`ai-hub-dev-template` / `aihub-demo`)には IRISSECURITY / DB 暗号化の実装は**存在しない**。
> 本手順は標準的な IRIS の暗号化手法に基づく**新規設計**である。

## 方針(確定済み)

- **暗号化キー**: 暗号化キーファイルを生成する(管理キー方式)。
- **起動時アクティベーション**: `IRISSECURITY` は起動の初期段階でマウントされるため、
  暗号化キーを**起動時に自動アクティベーション**する設定が必要。
- **対象**: `IRISSECURITY.DAT` を暗号化(必要に応じてユーザ DB も)。
- **デモ用の割り切り**: 鍵ファイルとアクティベーション用パスワードは `.env` / ファイルから供給する。
  本番環境では非推奨である旨を明記する。

## 検討事項 / リスク

- 起動時自動アクティベーションの設定方法(`.cpf` の `[Encryption]` セクション or 鍵ファイルの起動時アクティベーション設定)。
- 暗号化キーファイルとパスワードの管理(コミット禁止。`.gitignore` 済み: `*.key` / `encryption*.key`)。
- ビルド時に暗号化するか、初回起動(first-boot スクリプト)時に暗号化するかの選択。
  → 初回起動時実行なら `aihub-demo` の `start.sh` + `first-boot.sh`(センチネルで冪等化)パターンが有力。
